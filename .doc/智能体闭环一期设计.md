## 一、腰围前后分配口径：waist_balance = Δ（含守卫回喂）

### 1.1 口径

**腰围前后分配量默认等于臀围前后分配量 Δ**（用户口径 2026-09-29：打版惯例
"臀腰同调"，前后片侧缝对称分账）。Δ 已有五档预设路由（DELTA_PRESETS +
curvy/大差修正，derive.resolve_delta），waist_balance 不再有独立派生逻辑。

### 1.2 算术依据（病根与药）

水平分量近似（q = (H−W)/4）：

```
前侧收量 fi ≈ q + balance − Δ − ①前中内收 − ΔW袋口吃省
后侧收量 bi ≈ q − balance + Δ − Σ后省口
fi + bi ≈ (H−W)/2 − (ΔW + Σ省)        （与 K4 ④侧缝目标同账）
fi − bi = 2(balance − Δ) + Σ省 − ΔW − 前腰长调节
```

现状 `curvy_waist_balance` 是桩（恒 0，仅 curvy+skinny/slim 给 −0.5）：
curvy 款 Δ=1.35、高腰 ①≈2.5~3.0、ΔW=0.8 三项合计可超 q，**前侧收量塌零、
差额全压后片**——即症状 1 的完整配方。balance=Δ 代入后 Δ 项消掉：

```
fi ≈ q − ① − ΔW      （侧缝只管自己的四分之一份）
```

标准身材 q=5、①=1.25、ΔW=0.8 → fi≈3cm，回到健康区。

### 1.4 守卫与回喂（新模块 agent/extract/balance.py）

**判据只有一条：前侧塌零**（用户症状的直接度量——腰头侧缝点与臀侧点
共竖直线 = fi = 0）：

- 病态：`fi < 0.5` 且 H−W ≥ 10；豁免区 H−W < 10（直筒身材前侧近铅垂合法，
  不警不治）；
- 后侧不设带：balance 前减后加 1:1 对搬，前侧抬起来后侧自动让位；
- 阈值 0.5 是唯一待确认数字（用户口径确认即定，不做工厂定标；后续若见
  矫正过度/不足只调这一个数）。

**回喂**（复用毗围闭环哲学——重跑而非版上补丁，闭包不变量自动保持）：

- 挂载点：extract_from_input 内 `probe_loop` **L0 直接过**之后（L0.5/L1+
  已有回退语义，不叠加）；从 `probe.ctx` 量 fi（点名
  `front.waist_side_point` 与 `front.hip_outseam_point`，与 score 同源）；
- 步进：balance += 0.25，每轮重跑 `_run_once`（probe 内已有，毫秒级），
  ≤2 轮、累计 |Δbalance| ≤ 1.0；
- 到顶仍塌 → 取最接近的版 + 披露「守卫已达上限，建议核对腰臀尺寸」；
- **用户亲说优先**：waist_balance ∈ seed_overrides（映射账本设定过）时
  守卫只量只披露、不改值；
- 披露：进 delivery review + 报告（「侧缝守卫：前侧收量 0.2 塌零，
  waist_balance 1.35→1.60 重跑抬回」）。

score 与守卫共用同一塌零谓词（balance.py 单源）：score 增「前侧收量塌零」
警项、只警不改；守卫负责改。

## 三、意图层 + 定向复查（recheck）

### 3.1 意图本体

交卷后每轮的映射调用（现有节点，[adjust.py](../agent/extract/adjust.py)）
输出 schema 扩为：

```json
{"action": "adjust | recheck | none",
 "target": "部位组名（surface 分组名，action=recheck 时）",
 "adjustments": [ … ], "note": "…"}
```

prompt 增意图判据：要求再看/复查/仔细看某部位（「再看看 X」「X 不对吧」
「X 再确认下」）→ recheck；方向性修改意图（太大/太小/太凸…）→ adjust；
纯确认/寒暄/与版无关 → none。**recheck 时 adjustments 必须空**；note 面向
用户（「我来重新细看后贴袋的形状与大小」），杜绝「暂不改动」式不作为表述。
解析失败默认 action=adjust（即现状行为，天然回退）。总闸仍是
ADJUST_TRIGGER="off"。

### 3.2 部位组 → 复查键面与照片类别

target 词表 = adjust surface 的部位分组名（prompt 里已有）。代码侧映射：

| 部位组 | focus 键（MODEL_KEYS 子集） | 照片类别 |
|---|---|---|
| 前口袋 | front_pocket / facing / mouth_mode / mouth_depth / facing_mode / watch_pocket(+mode) / front_patch | front |
| 后贴袋 | back_patch / back_patch_shape | back |
| 腰头 | waistband_type / belt_loop | front+back |
| 育克·后片 | back_yoke / back_dart | back |
| 门襟 | fly / fly_separate | front |
| 版型·腰位 | fit / fit_level / waist_position | front+back |
| （兜底） | 全键 | 全部 |

### 3.3 recheck 执行器（新模块 agent/extract/recheck.py）

```
run_recheck(session, group, text, photos, photo_meta, provider, thinking)
  1. focus 键 + 判据手册仅该组段落 + 上次判断基线（vlm_cache 条目过滤）
     + 本轮用户原话 + 类别路由后的照片 → build_focus_prompt
  2. provider.complete → sanitize → obs 子集
  3. 与基线 diff → 变更清单（key, old, new, evidence）
  4. obs 经 extract_from_input 新参数 obs_inject 注入（跳过常规 S2 调用，
     与 prior 照 existing merge 语义：新覆盖旧同键；conf>0.5 + evidence
     门槛不变）→ 整条管线幂等重跑 → 交卷
  5. delivery 增 "recheck": {group, diff[…], note}——交卷摘要行披露
```

防翻烧饼三道闸：基线注入（推翻须写视觉证据）+ conf 门槛 + diff 披露。
复查是「带着上次答案的质证」，不是重新掷骰子。

### 3.4 照片回传握手

照片像素只在客户端；「重新分析」= 显式重传（session 设计预留口径）。

- **CLI**：照片路径跨轮全量在手，意图判定后同轮直接执行复查，一发完成；
- **Web 两段握手**（现状无 IndexedDB——[useSmartDraft.ts:3](../webapp/frontend/src/hooks/useSmartDraft.ts#L3)
  明确留后续，本期补最小实现）：
  1. 前端**内存留存**已提交照片：`sentPhotosRef = Map<category, File[]>`
     （send 成功时归档压缩后 File，约数百 KB×4，会话生命周期内有效；
     跨启动持久化仍留二期）；
  2. 轮次 A（仅文本）：后端意图=recheck 且本轮无照片 → append user 事件 +
     agent `directive` 事件（data={group, photo_categories}）→ 响应体增
     `directive` 字段；前端展示「正在复查背面照…」；
  3. 轮次 B（`fulfill="recheck"` + 类别照片，**指纹去重绕过**）：后端读
     会话尾部 pending directive → 执行 3.3 → 交卷；
  4. 留存无该类别照片 → 轮次 B 空照片 → 降级求援卡（按类别要照片，
     合法求援非反问）。
- 后端全程无状态：握手状态只存在于会话 JSON 的事件流里。

### 3.5 金标（语料先行）

- 意图语料 ≥ 20 条（含「后贴袋你再仔细看看」原话）：正例 recheck/adjust/
  none 各态 + 边界（「后贴袋形状不对，改成盾形」= adjust 带形态档位）；
  先攒语料再动 prompt（FakeVLM 单队列金标）；
- recheck diff 金标：基线 rectangle → 复查改 baker_shield 的 obs 覆盖与
  交卷披露；
- 两段握手状态机金标：directive → fulfill → deliver；空照片降级求援卡。
