# 智能体闭环功能点计划（腰围分配 / S2 瘦身 / 照片三类 / 意图复查）

## Context（为什么改）

三个实测症状：① 前片腰侧点与臀侧点共竖直线（前侧收量塌零）、后片臀腰差
巨大——腰围调节量未参与分配；② 照片不分视角，判据无法路由；③「后贴袋
你再仔细看看」被回复「暂不改动参数」——交卷后意图本体只有"调参"一个动作。

完整推导与算术依据见设计文档（本计划执行期间为口径权威）：
[.doc/智能体闭环一期设计.md](../../.doc/智能体闭环一期设计.md)。

## 已拍板口径（2026-09-29，用户确认）

- **waist_balance 基线推测 = Δ 终值**（臀腰同调惯例，随 DELTA_PRESETS 五档
  路由 0.25~1.35，非常数）；偏离规律（K5 表）等真实数据攒够再补，不预写；
- 塌零阈值 **fi < 0.5 且 H−W ≥ 10**（H−W < 10 直筒身材豁免）；后侧不设带
  （balance 前减后加 1:1 对搬自动让位）；
- curvy 大差款 **fi > bi 接受**（牛仔裤后片吃量靠育克与省道），旧「前 ≤ 后」
  S3 判据随旧口径退役；
- 照片**上传时手动三类**（front / back / other+用户描述），不做自动分类、
  不做类别置信度矩阵；
- 复查照片**不重传**（前端内存留存 `sentPhotosRef`；IndexedDB 跨启动不做）；
- 意图层**并入现有映射调用**（输出加 action 字段），不独立开调用；
- **不分期**：以下功能点全集一次规划、逐点交付。

## 硬约束（不可违反）

1. 分层红线：agent/webapp → ylpattern 单向；**引擎侧零改动**（本计划全部
   落 agent/、webapp/frontend、.doc/；waist_balance 引擎边界 ±8 已够）；
2. 零打扰原则重述：不反问澄清，但明确指令（复查）必须执行；
3. 后端无状态：recheck 握手状态只存在于会话 JSON 事件流，不落盘；
4. 会话 JSON 前后向兼容：vlm_cache.photos 旧字符串格式迁移 `{d,c:"any",n:""}`；
5. 单发 `agent extract` 行为逐位不变（仅会话路径 converse.run_turn 切换新逻辑）；
6. 意图解析失败默认 action=adjust（= 现状行为，天然回退）；总闸
   ADJUST_TRIGGER="off" 不动；
7. 判据/prompt 面变更必须跑 `scripts/eval_extract.py` 前后对比（CLAUDE.md 门禁）；
8. 写完停工作区，不代为 commit（用户口径）。
